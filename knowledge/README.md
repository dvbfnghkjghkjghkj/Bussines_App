# knowledge/ — база знаний проекта

Здесь лежит «сырьё»: материалы по нишам, ценам, конкурентам, шаблоны и заметки.
Это **не** код и **не** конфиг. Агент читает эту папку по запросу и на её
основе предлагает, что перенести в проект.

## Структура

| Папка | Что кладём |
| --- | --- |
| `niches/` | Описания ниш и бизнесов: чем занимаются, как продают, что важно клиенту |
| `pricing/` | Прайсы, диапазоны цен, условия аренды/смен, формулы расчёта |
| `competitors/` | Разборы конкурентов: сайты, сильные/слабые места, цены, офферы |
| `templates/` | Шаблоны текстов: офферы, описания услуг, сообщения в мессенджерах |
| `notes/` | Свободные заметки, наблюдения, вопросы к клиенту |

Допустимые форматы: `.md`, `.txt`, `.json`. Имена файлов — латиницей,
`kebab-case`, с датой при необходимости: `2026-11-arnet-ceny.md`.

## Как пользоваться

1. Положи файлы в нужную подпапку (можно в подпапки внутри неё).
2. Скажи агенту: **«изучи knowledge»** (или «что в папке знаний»).
3. Агент прочитает всё, сделает резюме и предложит **3–5 действий**:
   что использовать в проекте сейчас, что перенести в `config/company.json`,
   каких данных не хватает и какие файлы стоит добавить.
4. Агент **не меняет** эту папку без твоего подтверждения. Предложение — это
   предложение.
5. Итог разбора попадает в `docs/STATE.md`, раздел «Knowledge review».

## Чего здесь быть не должно

- Секретов: токенов, паролей, ключей API. Для них есть `.env`.
- Персональных данных клиентов без письменного согласия.
- Кода приложения — ему место в `src/`.
